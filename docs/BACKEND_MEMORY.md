## 4. Money flow (important) - NEW MODEL (12 Oct, owner request; replaces 'commission-free / direct to seller')
- **Seller buys a monthly or yearly platform plan** (admin creates/edits plans; free-trial plan optional) -> store. Yearly = `yearlyPriceUSD` or 12x monthly; web passes `interval` to `apiChangePlatformPlan`.
- **Platform fee per sale, set by admin** in Platform Config -> *Platform fees*: `PlatformConfig.platformFees {digital, physical}` each `{mode: percentage|fixed(USD per unit), value}`; educational/course count as digital; fee on item price only, never shipping. `FinanceService.recordSale(..., feeItems)`; falls back to old commission rules when unset. Seller-collected COD still debits the fee (`recordCodCommissionDebit`).
- **ALL buyer payments go to the PLATFORM account.** Card = platform Stripe. Bank/wallet = account the admin enters in Platform Config -> *Platform payment account* (`manualPaymentConfig`; `GET /api/payment/manual-transfer/bank-details`). Buyer uploads proof -> **admin approves** in Admin -> *Payment proofs* (`/admin/manual-payments`) -> order paid + `recordSale` credits seller wallet (sale minus fee, pending clearing). Seller direct bank (`Store.directPayment`) is retired: `/api/seller/manual-payments/*` return 410, DirectPaymentsPanel deleted.
- **Seller gets paid via wallet + payout request -> admin approves/sends manually** (finance module). `stripe-connect` still only onboarding/status (no destination charges).
- Seller credit is durable: `FinanceService.recordSaleDurable` writes `sale_credit_jobs` first, cron `*/5` retries with backoff (10 tries -> failed_final), admin alert (activity log) on first failure + final; admin tab *Failed credits* (`/api/admin/finance/credit-jobs`, retry). Fixed fee FX: order `fxSnapshots` -> `convertLastKnown` -> else job stays pending. Wallet/earnings responses now also have `platformFee*` names (old `commission*` kept as aliases).
- Payout methods store the **full account number encrypted** (`accountNumberEnc`, AES-GCM; key = `PAYOUT_ENCRYPTION_KEY` → `SEO_TOKEN_ENCRYPTION_KEY` → `JWT_SECRET`, first set; decrypt tries all). Seller screens only get last 4. Admin `GET /api/admin/finance/payouts/:id/destination` reveals it (audit-logged). Old payout methods had only last4 → seller must re-enter.
- COD (3 Nov): allowed for multi-seller physical carts, collected and confirmed PER PACKAGE (sellerOrder `isPaid/codAmount`, `markPaid` with `storeId`); digital items never COD (mixed carts use 'split').
- Currencies PKR/USD. Card only works on USD checkouts; PKR → bank transfer / COD. FX: daily cron from Frankfurter; if no rate exists the first need fetches one on demand. Admin → FX Settings overrides.
- No per-plan product-count limit any more (`assertCanCreateProduct` is a no-op).
